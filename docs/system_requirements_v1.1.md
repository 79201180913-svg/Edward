# Системные требования — Торговая платформа

**Версия:** 1.1  
**Назначение:** системные требования к Python-приложению, взаимодействующему с T-Invest API.

## Статус

Документ является исходной спецификацией версии 1.1. Требования SR-001—SR-115 принимаются как базовые требования к реализации. Открытые вопросы SR-OQ-001—SR-OQ-009 должны быть уточнены до финальной передачи спецификации в разработку.

## Архитектурные принципы версии 0.1

1. Python используется как основной язык реализации.
2. Интеграция с T-Invest API изолируется отдельным адаптером, чтобы бизнес-логика не зависела напрямую от конкретного транспорта API.
3. Production и Sandbox конфигурируются отдельно.
4. API Token не хранится в исходном коде и не попадает в пользовательский интерфейс, Excel или технический лог.
5. Торговая операция должна иметь идемпотентный идентификатор.
6. Перед отправкой заявки выполняются повторные проверки инструмента, торгового статуса, количества, цены, средств/позиции и типа заявки.
7. Состояние счета, баланса, портфеля и заявок считается актуальным только после получения данных от API.
8. История исполнений сохраняется локально в XLSX без возможности повторной отправки торговой операции из-за ошибки записи истории.
9. UI, API-клиент, доменная логика и хранение истории должны быть разделены по слоям.

## Требования

Полный набор требований SR-001—SR-115 и открытых вопросов SR-OQ-001—SR-OQ-009 принят из утвержденного пользователем документа в чате и является нормативной основой разработки.

### Ключевые функциональные области

- авторизация и работа со счетами;
- получение и идентификация финансовых инструментов;
- проверка доступности покупки/продажи;
- рыночные цены и минимальный шаг цены;
- денежный баланс и заблокированные средства;
- портфель и позиции;
- стоимость и доходность;
- отображение RUB/USD;
- покупка и продажа;
- лимитные, рыночные и иные поддерживаемые API типы заявок;
- предварительная валидация;
- комиссии;
- идемпотентность;
- мониторинг состояния заявок;
- частичное и полное исполнение;
- отмена и изменение активных заявок;
- уведомления;
- синхронизация после перезапуска;
- техническое логирование без секретов;
- обработка ошибок;
- сохранение фактических исполнений в Excel.

## Открытые вопросы

- SR-OQ-001 — источник и периодичность курса RUB/USD;
- SR-OQ-002 — канал уведомлений;
- SR-OQ-003 — частота обновления данных;
- SR-OQ-004 — параметры Excel-хранилища;
- SR-OQ-005 — выбор торгового счета;
- SR-OQ-006 — источник/формула доходности;
- SR-OQ-007 — источник предварительной комиссии;
- SR-OQ-008 — срок действия заявки;
- SR-OQ-009 — поведение при перезапуске.

## Критерий готовности

После уточнения открытых вопросов на базе этого документа должны быть сформированы API-спецификация, UI-спецификация, модель данных, схема взаимодействия с T-Invest API, обработка ошибок, QA-чек-лист, тест-кейсы и критерии приемки.
